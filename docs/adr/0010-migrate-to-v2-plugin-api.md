# Migrate to the opencode V2 plugin API

Supersedes ADR-0002. opencode 2 ships a new plugin API (`Plugin.define`, `plugins` config field, `opencode2` CLI); V1 plugins do not load there, and the team's installed binary is already V2-only. We migrated the plugin to the V2 API, pinned `@opencode-ai/plugin` to `0.0.0-next-17444` (exact match to the target release — the API is beta and may change), and adopted the native Effect route (`@opencode-ai/plugin/effect`, `effect@4.0.0-beta.101`) for plugin declaration, tool schema (`Schema.Union` of per-action structs discriminated on `action` — `Schema.discriminatedUnion`/`TaggedUnion` are broken in this effect beta build), and the typed `Tool.Error` failure channel. Real failures now throw; informational output stays a plain string (CONTEXT.md "Typed errors" rule).

**Considered options**: staying on V1 (rejected — the installed CLI is V2-only and ADR-0002's premise is a dead end), pinning the `beta` tag (rejected — that artifact still exports V1 as main; `tool`/`session`/`event` domains don't exist there), promise-flavored plugin with Effect schema only (rejected — "native with opencode" means the first-class Effect route), rewriting all 25 action bodies in `Effect.gen` (rejected — Effect buys nothing in file-conversion bodies; the boundary is wrapped once with `Effect.tryPromise`).

**Consequences**: dependency bump is breaking for V1 consumers — release as `v0.2.0`; tools are registered via `ctx.tool.transform(t => t.add(...))` with bare names and `options: { codemode: false }` (empirically verified at next-17444: default `codemode: true` exposes plugin tools only through the CodeMode `execute` wrapper — direct provider calls fail with "Unknown tool"; `codemode: false` restores direct calls, which is how agents use `officecli`/`edit`); a plugin tool whose name collides with a builtin replaces it in the catalog (verified: registering `edit` removes the builtin direct `edit` and routes calls to the plugin tool — so no `session.hook("context")` deletion is needed, and adding one would delete our own tool); plugin options (`pdfEngine`, `staleLockHours`, `dataDir`) arrive via `ctx.options`; V1-only scaffolding (`config`, `event` message log, `tool.execute.*` hooks, `dispose`) is deleted; INSTALL.md teaches the V2 `plugins` field and docs are refreshed in the same release.
