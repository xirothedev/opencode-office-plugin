# Ultracite Oxlint preset + oxfmt for lint and format

Adopted ultracite 7.12.0 as the versioned rule preset over the existing Oxc toolchain instead of migrating to Biome: `oxlint.config.ts` extends `ultracite/oxlint/core`, `oxfmt.config.ts` extends `ultracite/oxfmt`, with `oxlint@1.83.0` + `oxfmt@0.70.0` pinned exact per ADR-0016 policy. The bare-oxlint baseline was 12 scoped warnings; the preset enables 419 rules, so adoption required a big-bang refactor (~1600 findings, mostly `func-style`, `require-unicode-regexp`, `no-explicit-any`) plus one `oxfmt --write` baseline.

**Considered options**: bare oxlint + oxfmt without ultracite (rejected — drops the versioned preset the task requires, rules drift with each oxlint release); ultracite Biome backend replacing oxlint/oxfmt (rejected — double toolchain churn, invalidates the existing `lint` script and ADR-0016 pin policy); relaxed preset with noisy stylistic rules disabled (rejected by the Enduser — full strict accepted with the refactor cost).

**Consequences**: `bun run lint` is scoped to `src test scripts` and fails on any finding; `bun run format:check` gates formatting in CI via a new `format` job that blocks `build`; `tests/isolated-workspace/` fixtures stay ignored in `oxlint.config.ts` (test artifacts, not product quality); three intentional disables with reasons — `no-control-regex` in `sanitize.ts` (the C0-strip is the function's whole job), `unicorn/no-array-sort` in `verify-l3.ts` (fresh array, keeps lib at ES2022), `sort-keys` on the PPTX author attrs (key order is XML attribute order pinned by tests). Behavior-risky transforms from the refactor: `capture.ts` rethrows the original error object instead of a string; multi-file `accept` runs in parallel via `Promise.all`; test `harness.ts runTool` returns `Promise.reject` instead of `async`-throw to keep rejects-style assertions working; unicode-mode regexes required dropping `\:` escapes (bare `:` is literal).
