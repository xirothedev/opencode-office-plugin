# Isolated Runtime — tests/isolated-workspace

Strict isolation for `@xirothedev/openoffice-plugin-opencode`. No global plugins, no global MCPs. Proves the plugin works alone.

## Layout

```
tests/isolated-workspace/
├── opencode.json      # only this plugin, dataDir=.data, pdfEngine=weasyprint
├── package.json       # @opencode-ai/cli (opencode2) local, not global
├── scripts/tracer.mjs # Tracer Bullet: create→edit→read→history→revert per format
├── .capture/          # JSON traces + report.md (git keeps report.md)
├── .data/             # plugin dataDir: drafts/locks/history/registry/sidecars (gitignored)
├── docs/              # tracer outputs: tracer-*.docx|xlsx|pptx|pdf (gitignored)
└── node_modules/      # local opencode2 binary (opencode2, not opencode)
```

## Quick start (local)

```bash
# 1. install isolated opencode2 (once)
cd tests/isolated-workspace
bun install
bun pm trust @opencode-ai/cli   # allow postinstall to fetch binary

# 2. run tracer directly (no TUI, captures JSON, writes report)
bun run ./scripts/tracer.mjs
cat .capture/report.md

# 3. run isolated TUI via local binary (no global pollution via HOME override)
./scripts/run-isolated.sh
# inside TUI: "Create a docx at /tmp/.../tests/isolated-workspace/docs/hello.docx"
# TUI uses .data for drafts, not ~/.local/share/...

# 4. run via orca terminal (see below)
```

## Orca CLI — open isolated opencode session

Global opencode (`~/.opencode/bin/opencode` 1.18.25) loads 4 plugins + 6 MCPs. Isolated Runtime uses only this plugin.

**Recommended: orca terminal with HOME isolation**

```bash
# from any shell, open a terminal inside isolated workspace via Orca
orca terminal create --worktree active --title "isolated-office" --command "bash ./tests/isolated-workspace/scripts/run-isolated.sh" --json

# or if you are already in Orca, just:
orca terminal list --json
orca terminal send --terminal <handle> --text "bun run ./scripts/tracer.mjs" --enter --json
```

`run-isolated.sh` sets `HOME=$PWD/.home` so global `~/.config/opencode` and `~/.opencode` are not read. Only `tests/isolated-workspace/opencode.json` is used. Data stays in `.data`.

**Alternative: orca worktree (git-isolated fix branch)**

If you want a git-isolated fix branch that shares the same Isolated Runtime:

```bash
orca worktree create --name office-isolated-fix --agent codex --prompt "Run tests/isolated-workspace/scripts/tracer.mjs, fix any FAIL in src/, rebuild, re-run tracer until all PASS, update .capture/report.md" --json
```

Fixes are done in main repo `src/` (In-place Fix), rebuilt (`bun run build`), re-verified by re-running the same Isolated Runtime.

## Capture & Report

- **Capture**: `scripts/tracer.mjs` writes one JSON per `officecli` invoke to `.capture/<ts>-<label>.json` with `{label, args, output, error, ms}`.
- **Report**: `.capture/report.md` summarizes PASS/FAIL per format and links to captures. Generated by tracer, also hand-editable.

## In-place Fix loop

1. Tracer fails (e.g. `xlsx: FAIL — No markdown table found`)
2. Fix in `src/` (not in `tests/isolated-workspace`)
3. `bun run build` (root)
4. Re-run tracer: `cd tests/isolated-workspace && bun run ./scripts/tracer.mjs` or via orca terminal
5. Repeat until `report.md` shows all PASS

Historical fix: `src/core/draft/manager.ts:91` now `mkdirSync(getHistoryDir(), {recursive:true})` before `writeFileSync(history)` — fresh dataDir no longer ENOENT on first accept.

## Notes

- `opencode` (1.18.x) vs `opencode2` (0.0.0-beta-*) are different CLIs. Isolated uses `opencode2` (beta) because `opencode.json` plugins field is V2 API. Use `./node_modules/.bin/opencode2` not global `opencode`.
- `pdfEngine=weasyprint` because `xelatex` not installed on macOS; `weasyprint` is present at `/opt/homebrew/bin/weasyprint`. Change in `opencode.json` options if you install another engine.
- `xlsx` requires markdown table; tracer's `finalContent` for xlsx is a table, not free text.
